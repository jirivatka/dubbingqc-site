Read this first

Dubbing QC compares a dubbed dialogue stem with the original-version (OV) dialogue stem and lists the places a dub mixer should listen to: missing lines and efforts, reverb and pan that differ from the OV, voice treatments that weren't copied, sync slips, cut-off line ends, clicks and more. The result is a set of markers for your own session and a PDF report.

Thresholds are measured — against real delivery-QC reports, planted defects, and listening tests — not guessed.

The findings are candidates, not verdicts.Every marker is a place to listen. The app never changes your audio and never sends it anywhere.

Install

  1. Open Dubbing QC 0.8-alpha.dmg and drag Dubbing QC onto the Applications folder.
  2. Start it from Applications. The first time, macOS asks whether you want to open an app downloaded from the Internet: click Open. The app is signed and notarised by Apple, so there's no "unidentified developer" block, even offline.
  3. The first time it reads a folder on your Desktop, Documents or an external drive, macOS asks whether Dubbing QC may access it. Click Allow. Until you answer, the folder card says Reading the folder…

Nothing else is installed: no drivers, no plug-ins, no account.

Prepare the files

Each version is one folder of split-mono 5.1 WAV files, one file per channel, named with the channel at the end:

Original version/ Dub/ Show_E01_OV.L.wav Show_E01_DUB.L.wav Show_E01_OV.R.wav Show_E01_DUB.R.wav Show_E01_OV.C.wav Show_E01_DUB.C.wav Show_E01_OV.LFE.wav (optional) Show_E01_DUB.LFE.wav Show_E01_OV.Ls.wav Show_E01_DUB.Ls.wav Show_E01_OV.Rs.wav Show_E01_DUB.Rs.wav
  • Use the dialogue (DX) stems, not full mixes. The OV folder holds the original-language DX, the dub folder the dubbed DX.
  • Both versions must be the same length and on the same timeline, starting at the same first sample. They may carry different embedded start timecodes (for example 00:00:00:00 and 08:00:00:00).
  • Tested with 48 kHz / 24-bit. Frame rates 23.976, 24, 25, 29.97 (drop-frame or not), 30, 50, 59.94 (drop-frame or not) and 60 fps. Drop-frame timecode is written with a semicolon, 01:00:00;00.

Check an episode

  1. Drop the OV folder on the Original version card and the dub folder on the Dub card (or use Choose…). Each card then shows the format it found, for example 5.1 split mono · 48 kHz · 24-bit · 0:56:10.
  2. Check the frame rate. Session start TC can stay empty: the dub file's embedded start time (BWF) is used, so markers land in your session's timecode.
  3. Optional: under Printmasters, add the OV and dub printmaster folders (split-mono 5.1, named like the stems). The two mixes are then lined up on their shared M&E to the millisecond: a whole-mix offset, a dropped or added frame, or a slipped section is found, and the dub DX stem is checked against its own mix. File QC also compares the two printmasters' loudness: the dub must match the OV within ±0.5 LU (adjustable in Thresholds).
  4. Press Run QC or ⌘ ↩. An episode takes about 20 seconds (about 6 minutes with speech recognition on).
  5. Press Export and choose a folder. See Markers in your DAW.

Hover over any control for a short explanation.

Read the results

  • Tiles: one per check, with the number of findings. Red is a blocker (missing lines and efforts), orange a major issue, a green tick means nothing was found, and off means the check did not run. Click a tile to show only those findings in the table; click it again to show all.
  • File QC: format, length, loudness (BS.1770), peaks, clipping, channel layout and room tone for both versions, and the dub's file names against the OV's: the frame rate in the name must match the session (Fail), the episode, version and stem must be the OV's (Fail), and any part missing, added or out of order compared with the OV's name is a Fail too. The File QC strip names the first failure and why, without opening Details. Details opens the full list.
  • Review markers: candidates the audio can't judge on its own, exported as separate marker files to step through against picture (see below).
  • The table: every finding with its session timecode, length, type and what was measured.

Main markers and review markers

Three checks produce far more candidates than anyone wants in a session, and nothing in the audio says which ones a QC operator would flag:

  • Missing efforts (breaths, laughs, reactions): the 20 most audible become main markers; all the others, often 250 or more, go into an effort review file.
  • Level jumps (a line much louder or quieter against the OV than its neighbours): all go into a level review file. In practice, most of them are intended performance differences.
  • OV audio in the dub (the dub reuses the original recording: a kept song, walla, a breath): all go into an OV audio review file. In practice, every one is intended. Listen for an original-language line that should have been dubbed. With speech recognition on, any words heard are shown (OV AUDIO, WORDS HEARD?), but sung lyrics are recognised too.

Import the review files onto a separate marker track, or leave them out.

Markers in your DAW

The Include review markers switch in the same menu decides whether the effort, level and OV audio review files are added to marker exports.

Pro Tools

  1. File › Import › MIDI… and choose the .markers.mid file.
  2. Destination: Clip List (no MIDI track is created). Location: where the stem starts in your session.
  3. Leave Import Tempo Map from MIDI File off if the session runs at 120 BPM, the default. The markers are written at 120 BPM; at another tempo they land in the wrong place.

Markers arrive as memory locations.

Nuendo / Cubase

  1. Project › Project Setup: set the frame rate the report used.
  2. File › Import › Marker from CSV, choose the .markers.csv file.
  3. Assign columns: Name → Name, Timecode In → Start, Timecode Out → End, Description → Description. Using Category as the split column gives one marker track per kind of problem.

Timecodes in the CSV are absolute session timecode.

Logic Pro

File › Open… the .markers.mid file: a new project opens with all markers.

Check a season

  1. Switch the header from Episode to Season.
  2. Drop a folder holding one subfolder per OV episode, and one holding one subfolder per dub episode.
  3. Check the pairing table. Episodes pair by the episode code in the folder or file name (S01E05, E0018, EP05…). Without codes, they pair in name order, but only if both sides have the same number. Anything unpaired is listed; nothing is guessed.
  4. Optional: under Printmasters, add an OV and a dub printmaster season folder (again one subfolder per episode). They are matched to the episodes by their code; the table's Printmasters column shows which episodes have both. Episodes without them are checked from the dialogue stems alone.
  5. Run season asks once where to save, then checks the episodes one after another. Each gets its own folder as soon as it's done, and Season summary.csv gets one row per episode. A broken episode is reported and the rest carry on.

Click an episode in the table to see its results.

Studio and project details

  • Studio (Dubbing QC › Settings… › Studio, set once): studio name, contact for the PDF footer, a default "QC by" name and a logo.
  • Project (the document button in the header, per job): delivery profile, production, client, episode (read from the file name, editable), dub language, QC by, version/delivery and notes. They're remembered for the next episode; the button always shows the production and episode so an old name doesn't slip onto a new report.

They're printed on the PDF, in the marker README and in the season summary, and stored on your Mac only.

Thresholds and delivery profiles

Dubbing QC › Settings… › Thresholds is a library of delivery profiles — named sets of which checks run and their limits (sync shift, reverb gap, pan, EQ, how many efforts are marked, and others). Measured defaults is built in and can't be edited or deleted; duplicate it to start your own profile for a client's house rules, then edit, rename or delete your copy freely.

Pick which profile a job uses in the Project popover, next to production and client — so it travels with the job, not with the Mac. A profile can be exported to a file and shared with a freelance mixer working the same show, and imported the same way.

Any profile other than Measured defaults is printed as custom, unverified everywhere it shows up — the header badge, the PDF, the marker README. A loosened or custom run can never be mistaken for the standard one.

Speech recognition

Two checks can use speech recognition: confirming a missing line by its actual words, and finding original-language speech left in the dub. It's off by default (the switch under the frame rate).

When switched on, recognition runs only on your Mac, with Apple's on-device model; the audio is never sent anywhere, which was checked by logging every network connection during a full run. macOS asks for permission once, and its standard dialog says speech data "will be sent to Apple" — that is Apple's wording for every app. You can leave it off: every other check works without it.

The OV language needs an on-device model (a ✓ in the language menu; English is always there). The dub's language needs none.

Known limits

  • Expect occasional false alarms and misses on unusual material — every threshold is a measured default, not a guarantee, and can be adjusted in Thresholds.
  • Sync is measured against the OV audio, not lip-sync against picture. From the dialogue stems alone only whole-line shifts of about 0.8 s and more are found; add the printmasters for frame-accurate sync.
  • Which breath a QC operator flags depends on the picture, so efforts are ranked, not judged.
  • Walla is only marked with both printmasters; without them the candidates go to a review file.
  • Split-mono 5.1 input only for the OV and dub dialogue stems; no interleaved files. A printmaster may instead be a stereo (2.0) downmix (10-08) — sync and loudness run on it the same way, but comparing it against the full 5.1 dub dialogue stem (the "Dub DX inside the dub printmaster" row) is unreliable, since the two sides then have different channel counts.
  • 23.976 and drop-frame are new: checked against the published timecode tables, but not yet on a real session at those rates.

Troubleshooting

You seeWhat to do
The application "Dubbing QC" can't be opened.The disk image was altered on its way to you: WhatsApp and some other chat apps re-package files they send. Get the .dmg by e-mail, AirDrop or a download link instead, delete the broken copy from Applications, and install again.
A card stays on Reading the folder…macOS is waiting for your answer to its folder-access question; the dialog may be behind other windows. Click Allow.
No .L.wav file in …The folder has no file ending in .L.wav. Check the channel names (see Prepare the files).
Markers land at the wrong place in Pro ToolsCheck the session runs at 120 BPM, and that the import location is where the stem starts.
Markers are shifted by hoursThe stem's embedded start time differs from your session. Enter the session start in Session start TC and export again.
The OV language tile says offSpeech recognition is off, or there is no on-device model for that language. Everything else ran normally.
A run is much slower than usualOther heavy apps slow it down, especially with speech recognition on.
